SysMon One v7.1.1 — 使用说明（简体中文）
================================================================================

这份文档写给第一次打开 SysMon One 的人。只讲怎么用、看到的东西是什么意思、
以及哪些事它故意不做。全文没有宣传词，也不和别的工具比较。


1. SysMon One 是什么
--------------------------------------------------------------------------------

SysMon One 是一个单文件的本地系统监控 / 诊断 / 磁盘清理工具。

  - 单个文件：macOS 是一个 .command（内嵌 Python 3），Windows 是一个 .cmd
    （内嵌系统自带 PowerShell）。不需要安装任何东西，不需要 pip / npm。
  - 免 sudo：标准功能全部在普通用户权限下工作。
  - 纯本地：不联网、不发送遥测、不需要账号、不装后台服务、不带自动更新。
  - 诚实优先：读不到的传感器一律显示 N/A，不会编一个看起来合理的数字给你。
  - 保守清理：只清理可重建的缓存与诊断文件；个人文件永不进入自动删除路径。

当前版本 v7.1.1。macOS 主线已在真实机器上验证启动正常
（Mac16,11 / Apple M4 Pro / 24 GB / macOS 27.0 build 26A5425a）。
Windows 版属于 Beta，仍在等待更多真实机器反馈。


2. macOS 怎么运行
--------------------------------------------------------------------------------

  1) 从 Release 页面下载 SysMon-One-v7.1.1-macOS.zip。
  2) 解压（不要只把里面的 .command 单独另存出来——那样会丢执行权限）。
  3) 双击 SysMon-One.command。会打开一个终端窗口，界面就地刷新。

基本操作：

  C   打开磁盘医生（Storage Doctor）
  P   打开进程中心（Process Center）
  /   搜索进程
  Q   退出
  Ctrl+C  退出（任何界面下都有效）

命令行参数（可选）：

  --lang zh|en     强制语言
  --compact        紧凑布局
  --expert         展开更多细节
  --doctor         直接进入磁盘医生
  --clean          执行绿色安全项清理流程
  --scan           只做磁盘扫描并输出结果
  --interval 2     刷新间隔（秒）

说明：界面宽度会自动适配终端窗口；窗口越大，一行能放下的核越多。


3. Windows 怎么运行
--------------------------------------------------------------------------------

  1) 从 Release 页面下载 SysMon-One-v7.1.1-Windows.zip。
  2) 解压。
  3) 双击 SysMon-One-Windows.cmd。它会调用系统自带的 PowerShell 运行，不需要 Python。

注意：

  - 需要系统自带 PowerShell（Windows 10/11 默认就有）。
  - 当前为 Beta：真实机器验证仍在进行，请把异常反馈给我们（见第 18 节）。
  - 风扇数据只在 Windows / OEM 或受支持的传感器提供方暴露时才显示，否则是 N/A。


4. 主界面指标是什么意思
--------------------------------------------------------------------------------

主界面从上到下大致是这些块：

  机型 / 芯片 / 构建   硬件型号、SoC、系统构建号
  负载                 系统 load average（1 / 5 / 15 分钟）
  CPU                  总占用、逐核或逐簇的频率与使用率、有效频率
  GPU                  GPU 核、频率、GPU Active
  内存                 已用 / 可用 / 压缩
  Swap                 已用 / 容量、换入换出速率
  Memory Pressure      实时内存压力：NORMAL / WARN / CRITICAL
  磁盘                 容量、读写速率
  网络                 上传 / 下载速率
  温度 / 风扇          温度传感器、风扇转速（不支持则 N/A）
  电池                 充电 / 放电状态、瓦数、电量趋势
  趋势                 最近约 60 秒的变化
  进程数 / 高负载进程   当前进程统计，以及值得看一眼的进程

界面里的数值来自系统公开或半公开的计数器；读不到就是 N/A，保持诚实。


5. CPU / GPU / RAM / Swap
--------------------------------------------------------------------------------

CPU
  总占用是所有核心使用率的加权结果。逐核视图会按簇分组（Apple Silicon 上
  通常分为能效核与性能核）。有效频率是当前实际运行频率，不是"最高能跑多少"。

GPU
  显示 GPU 频率与 GPU Active。注意：GPU Active 指的是"非 OFF 驻留时间"所占比例，
  它是可观测的事实，不等于驱动层的 utilization 计数器——我们不会把前者冒充后者。

RAM
  内存块显示已用、可用与压缩内存。macOS 会把不活跃的内存压缩起来，所以
  "已用"里可能包含相当一部分压缩数据，这属于正常行为，不是内存泄漏。

Swap
  显示交换区已用 / 容量，以及换入（swap-in）与换出（swap-out）的实时速率。
  速率比绝对值更值得关注：稳定的高占用但零换入换出，通常比低占用但持续狂换要好。


6. 为什么 Swap 很大不一定需要清
--------------------------------------------------------------------------------

这是最容易被误判的一项。Swap 占用很大，本身并不是故障：

  - 系统会把长时间不用的内存页换出去，这是正常的调度行为。
  - 很多进程会把大块内存换出后就不再碰它；占着 Swap 并不等于正在消耗性能。
  - 真正影响手感的是"换入换出是否在持续发生"，以及内存压力是否升高。

所以判断标准是：

  - Memory Pressure = NORMAL，且换入换出速率接近 0  -> 占用大也没关系，不要动它。
  - Memory Pressure = WARN / CRITICAL，或换入换出持续很高 -> 这时才值得处理，
    优先看看内存 Top 进程，而不是为了把数字清零去强杀进程。

另外，进程列表里的 Swapped（压缩 / 换出的进程内存）不等同于磁盘上的精确 Swap
数值，两者统计口径不同，不要混着看。

一句话：不要为了几个漂亮的零，把正常系统优化成事故现场。


7. Memory Pressure 是什么
--------------------------------------------------------------------------------

Memory Pressure 是系统层面的"内存压力"状态指示灯，取值为：

  NORMAL    正常
  WARN      有压力
  CRITICAL  严重

它综合反映了系统在内存分配上是否吃力。界面里还会给一个实时压力指数，那是
基于当前状态计算的启发式指标，用来观察趋势，不是性能评分，也别拿它和别的机器比。


8. C：磁盘医生（Storage Doctor）
--------------------------------------------------------------------------------

按 C 进入。它会扫描常见的空间占用来源，并给出分类建议，例如：

  - 应用缓存（30 天以上）
  - 崩溃报告（14 天以上）
  - 安装包 / 压缩包
  - 大文件
  - 废纸篓
  - 用户目录空间分布（HOME MAP）

三档含义见第 14 节。清理动作只会作用在"绿色安全项"上；执行前需要确认（输入 y）。


9. P：进程中心（Process Center）
--------------------------------------------------------------------------------

按 P 进入，子菜单：

  [1] 当前用户进程树      以树形展示当前用户的进程关系
  [2] CPU/RAM Top20      按 CPU 与内存排序的进程榜
  [3] 搜索进程            按名称 / 命令行搜索
  [4] 结束进程 PID        输入 PID，按第 11 节的信号策略处理
  [0] 返回监控


10. /：搜索
--------------------------------------------------------------------------------

按 / 直接搜索进程（等价于进程中心里的 [3]）。输入名称或命令行的片段即可，
搜索是大小写不敏感的子串匹配。搜到之后可以回到进程中心继续用 [4] 处理。


11. Kill 的 TERM / KILL 区别
--------------------------------------------------------------------------------

SysMon One 结束进程时是两步走：

  第一步  TERM（正常退出请求）
          告诉进程"请自己收尾并退出"。进程可以保存文件、关闭连接、释放资源。
          大多数进程在这一步就结束了。

  第二步  KILL（强制结束）
          只有第一步没成功时才会用到，并且需要你再次输入 y 明确确认。
          强制结束不会给进程任何收尾机会，未保存的数据可能直接丢失。

所以界面上的提示不是装饰：进程仍在运行时会明确告诉你
"进程仍在运行。强制 Kill 可能造成未保存数据丢失。"


12. 为什么系统进程不允许杀
--------------------------------------------------------------------------------

部分进程被明确保护，拒绝结束请求：

  - 系统关键进程：结束它们可能导致系统不稳定、界面无响应，甚至需要重启。
  - 当前工具自身进程：避免把自己杀掉导致界面消失。
  - 其他用户的进程：免 sudo 模式下不处理（这也是"免 sudo"的代价之一）。

这不是功能缺失，而是设计边界：一个监控工具不应该具备轻易搞坏系统的能力。


13. 风扇显示 N/A 是什么意思
--------------------------------------------------------------------------------

风扇一行可能出现 N/A，含义是"本机不提供这个读数"，常见原因：

  - 机型本身无风扇（例如部分 MacBook Air）。
  - 传感器不通过当前可用的接口暴露。
  - 本次读取被系统拒绝或超时。

N/A 就是 N/A，我们不会用估算值填空。主监控界面的其他指标不受影响，继续可用。

v7.1.1 的修复说明：v7.1.0 在部分 Apple Silicon + 系统自带 Python 3.9 环境下，
初始化风扇传感器时会把 Darwin 的 mach_task_self_ 数据符号误当函数调用，
导致进程崩溃。v7.1.1 改为按数据符号读取该 Mach port，并加了 ABI 尺寸校验；
读不到就降级为 N/A，主界面继续工作。


14. Storage Doctor 的三档
--------------------------------------------------------------------------------

  绿色安全项    可重建的缓存 / 诊断文件。删掉它们最多是让系统或应用重新生成一遍。
                可以一键清理全部绿色项（需要输入 y 确认）。

  黄色人工检查  可能占很多空间，但删不删由你判断（例如较大的下载内容、旧安装包）。
                只展示，不自动删。

  红色保护项    受保护的内容，不会自动删除。

界面上的原话是：绿色 = 可重建缓存 / 诊断文件；黄色 = 可能很大，但由你判断。
我们不会靠把个人文件叫"垃圾"来制造好看的数字。


15. 不会自动删除的目录
--------------------------------------------------------------------------------

以下内容永远不会进入自动删除路径，只做展示或提示：

  桌面 / 文稿 / 照片图库 / iCloud Drive / 邮件 / 信息 / 项目文件
  （桌面、下载目录中的个人内容同样只展示、不自动删除）

如果你希望释放这些地方的空间，请自己确认文件用途后再手动处理。


16. macOS 权限 / Gatekeeper 解决办法
--------------------------------------------------------------------------------

情况一：双击提示"没有执行权限"或文件无法打开
  -> 请从 Release 的 ZIP 解压后再运行，不要从聊天窗口把 .command 单独另存出来
     （另存会丢执行位）。

情况二：Gatekeeper 提示"无法验证开发者 / 来自身份不明的开发者"
  -> 打开"系统设置 -> 隐私与安全性"，在安全提示处选择"仍要打开"。
     之后双击即可正常运行。

情况三：想手动恢复执行权限（终端里执行一次即可）
  -> chmod 755 SysMon-One.command

以上都只涉及本机文件权限，不涉及任何账号或联网授权。


17. Windows PowerShell 提示处理办法
--------------------------------------------------------------------------------

  - 双击 SysMon-One-Windows.cmd 即可。脚本自身以 -NoProfile -ExecutionPolicy Bypass
    的方式调用系统 PowerShell，一般不会触发执行策略拦截。
  - 若被 SmartScreen 提示"Windows 已保护你的电脑"，选择"更多信息 -> 仍要运行"。
    （这是对未签名脚本的常规提示。）
  - 若系统提示找不到 PowerShell，请确认 Windows 10/11 的 Windows PowerShell
    组件未被移除。
  - 建议右键"以普通用户身份运行"，本工具不需要管理员权限。


18. 如何提交 Bug
--------------------------------------------------------------------------------

请在 GitHub Issues 里使用 Bug Report 模板，并填齐：

  - SysMon One 版本（界面顶部，例如 v7.1.1）
  - 操作系统与版本
  - 硬件型号
  - CPU / SoC
  - 内存容量
  - 发生了什么
  - 期望结果
  - 复现步骤
  - 截图或终端输出
  - 是否每次都复现

提交前请务必删除：用户名、私人路径、IP 地址、Token / API key、邮箱、系统密码、
私有文件内容。模板里有这一项确认框。

关于传感器：不同厂商、不同 SoC 能提供的数据本来就不一样。某个传感器读不到
通常不是 Bug，而是硬件或系统没暴露；这类情况可以直接说明，我们会如实标注 N/A。

安全漏洞请不要开公开 Issue，走仓库 Security 页面的私密漏洞上报（Private
Vulnerability Reporting）。详见 SECURITY.md。


附：安全边界（完整清单）
--------------------------------------------------------------------------------

  - 不需要 sudo
  - 不联网、不发送遥测、不需要账号
  - 不安装后台服务、不带自动更新
  - 不自动删除个人文件
  - 系统关键进程受保护，不允许直接结束
